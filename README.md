# 静音カメラ（Web）

シャッター音の鳴らないカメラを Web で作り、iOS のホーム画面に追加して疑似アプリとして使う。
広告なし・アカウント不要・写真は端末の外に出ない。ビルド不要の静的サイト。

## なぜ無音になるのか

iOS の写真撮影 API（`AVCapturePhotoOutput`）は、日本・韓国向けの端末ではシャッター音の抑止が
許可されていない（`isShutterSoundSuppressionSupported` が `false`）。一方で **カメラの映像ストリームから
フレームを切り出す経路は写真撮影 API を通らない**ため、音は鳴らない。市販の無音カメラアプリと同じ原理で、
これは Web の `getUserMedia` でもそのまま成立する。

| 経路 | 実体 | 音 |
|---|---|---|
| `drawImage(video)` / `ImageCapture.grabFrame()` | 映像フレームのコピー | **構造的に鳴らない** |
| `ImageCapture.takePhoto()` | WebKit 内部で `AVCapturePhotoOutput` | 実測では鳴らなかった（保証はない） |

このアプリの既定は前者。`takePhoto()` は「単写」モードとして分離してあり、選ぶと確認が出る。

## 画質について

映像フレームは純正カメラの写真パイプライン（Deep Fusion / Photonic Engine）を通らないので、
1 枚撮りでは純正に劣る。そこで **静音のまま多フレーム合成**する「合成」モードを用意した。

- 連写したフレームをサブピクセル精度で位置合わせし、リニア光で加算平均する
- ランダムノイズは枚数 N に対して 1/√N で減る（16 枚で約 1/4）
- 8bit 素材でもノイズがディザとして働き、平均化で中間階調が戻る
- 手ぶれによるサブピクセルのずれを利用し、2 倍格子に落として超解像（ドリズル）できる
- 基準フレームから大きく外れた画素は重みを落とすので、多少の動体はゴーストになりにくい

**得意**: 静止した被写体、暗所のノイズ、階調と色の滑らかさ。
**不得意**: 動く被写体、純正の 48MP 相当の解像感。原理的に超えられない部分は正直に諦めている。

## 使い方

1. HTTPS で公開されたページを iPhone の Safari で開く
2. 共有 → 「ホーム画面に追加」
3. ホーム画面のアイコンから起動する（前回の許可が残っていれば、そのままカメラが開く）
4. 撮影 → 「保存」 → 共有シートの「画像を保存」で写真アプリへ

## モード

| モード | 内容 |
|---|---|
| 即写 | 映像フレームを 1 枚切り出す。0ms。広色域（Display P3）を保てる |
| 合成 | 連写 → 位置合わせ → 合成。枚数と 2 倍格子は設定で変更できる |
| 単写 | `ImageCapture.takePhoto()`。品質 1.0 の JPEG が直接返る。1 枚 1 秒ほどかかる |

**単写（写真 API）について**: 手元の iPhone（iOS 18.7）では**全解像度でシャッター音が鳴らなかった**。
ただし WebKit 側に音を止める処理は無く、OS の強制対象から外れているだけなので、
機種や iOS の版によっては鳴る可能性がある。初回は確認ダイアログを出している。
無音が保証されるのは、写真撮影 API を通らない即写と合成の 2 つ。

実測では **単写でも解像度は映像と同じ**（高解像にはならない）で、**速度は 5〜10 倍遅い**
（即写 45–214ms に対し 335–589ms、初回は 1.0–1.4 秒）。画質の優劣は条件依存だったため、
**既定は即写**にしてある。詳しい数字は `docs/FINDINGS.md` を参照。

## カメラの許可

ホーム画面 Web アプリは起動のたびに新しい文書になるため、前回の許可が残っていないと
毎回プロンプトが出る。これは WebKit 側の制約で、Web 側から消す手段は無い。
代わりに**出さずに済むプロンプトを全部なくして**ある。

- 起動時に `getUserMedia` を呼ぶ前に許可の有無を推定し、残っていれば**自動でカメラを開く**
  （開始ボタンを押す手間も無くなる）
- 解像度の変更はストリームを作り直さず `applyConstraints` で済ませる
- バックグラウンド復帰ではトラックが生きていれば何もしない
- 別ページへ移動する前に確認を出す（移動すると文書が変わり、許可を取り直しになる）

毎回聞かれる場合は、設定 → アプリ → Safari → カメラ を「許可」にすると出なくなることがある
（全サイトに許可が下りる点に注意）。その端末で許可が残るかどうかは、
`diag.html` の「0b. 許可の持続」を**アプリを閉じて開き直してから**実行すると分かる。

設定では合成枚数・2 倍格子・シャープ・解像度・保存形式・画質と、「合成中は 60fps を要求」を
切り替えられる。ズーム（0.5×/1×/2×）とライトは、端末が対応していれば自動的に表示される。

## 診断ページ

`diag.html` は実機の実力を測るためのハーネス。解像度ラダー、トラックの能力、フレーム取得経路の速度、
連写レート、`takePhoto` の挙動（**音の有無を手動で記録**）、GPU、書き出し形式を調べ、JSON で出力する。
結果は `docs/FINDINGS.md` に貼って端末ごとに記録する。

## 開発

```sh
npm test          # 位置合わせと合成の単体テスト（依存なし）
npm run test:e2e  # Chromium での結合テスト（要 playwright。偽カメラで撮影まで通す）
npm run icons     # アイコン PNG を再生成
npm run serve     # ローカル確認（カメラは https か localhost でのみ動く）
```

GPU シェーダは CPU 実装（`accumulate.js`）と同じ式で書いてあり、`diag.html` の
「GPU/CPU 一致テスト」で同じ入力を両経路に通して一致を確認できる。

### 検証済み / 未検証

Chromium（偽カメラ）で、1 枚撮影・合成・2 倍格子・写真 API・診断ページが通ることを結合テストで確認済み。
GPU シェーダは CPU 実装と **canvas 入力でも ImageBitmap 入力でも**一致する（実機でも maxDiff 0）。

実機（iPhone / iOS 18.7）で分かったことは `docs/FINDINGS.md` にまとめてある。要点だけ挙げると:

- **4K（2160×3840 @30fps）で撮れる**。「iOS Safari は 720p まで」という古い記述は現行では誤り
- `grabFrame` は遅い（480×640 で 34ms）。`new VideoFrame(video)` は**回転したフレーム**を返す
- ズームが 0.5–10 で効く（0.5× は超広角）。ライトも使える
- **`takePhoto()` は全解像度で無音**だったが、解像度は映像と同じで速度は 5〜10 倍遅い
- 写真 API にサイズを要求しても映像と同じ大きさに丸められ、**能力値の最大を要求したときだけ落ちる**
- `toBlob('image/heic')` は **実体が PNG** だった。`blob.type` は当てにならないので実体を検査している

**まだ実機で確かめられていないこと**:

- ホーム画面起動時にカメラ許可が保持されるか（`diag.html` の「0b. 許可の持続」で判定できる）

## 公開（GitHub Pages）

リポジトリ設定 → Pages → Branch を選んで公開する。ビルド手順は不要。
`.nojekyll` を置いてあるので、ファイルはそのまま配信される。

## 構成

```
index.html                本体（単一ページ。リロードしないので許可を聞かれにくい）
diag.html                 実機計測ハーネス
src/camera.js             getUserMedia・解像度ラダー・能力適用
src/capture/frame.js      無音フレーム取得（経路を実測して選ぶ・回転する経路は弾く）
src/capture/burst.js      連写・リングバッファ・ブレ評価
src/capture/photo.js      単写（写真API。実測では無音だが保証はない経路）
src/pipeline/align.js     ピラミッド＋放物線フィットのサブピクセル位置合わせ
src/pipeline/accumulate.js 合成の中核（純関数・テスト対象）
src/pipeline/merge.js     WebGL2 による GPU 合成
src/pipeline/cpu-merge.js CPU フォールバック
src/pipeline/stack.js     連写→位置合わせ→合成の司令塔
src/encode.js             書き出し・形式の実体検査・共有シート保存
src/permission.js         プロンプトを出さずに許可の有無を推定
```

## プライバシー

撮影した画像はページ内で処理され、どこにも送信されない。Service Worker は静的ファイルのみを
キャッシュし、画像は一切保存しない。

## 注意

盗撮など違法な用途には使用しないこと。日本では 2023 年 7 月施行の性的姿態等撮影罪をはじめ、
撮影行為そのものを処罰する規定がある。
