# 静音カメラ

iPhone のブラウザで動く、シャッター音の鳴らないカメラである。
Safari で開いてホーム画面に追加すると、全画面のアプリとして起動する。

https://nekonekokananeko00000-svg.github.io/IOS-Cam.web/

A silent camera that runs in a browser on iPhone. It saves a still frame taken
from the camera preview instead of calling the system photo API, so the shutter
sound is not played. Images are processed on the device and are never uploaded.

## 仕組み

日本国内向けの iPhone は、カメラのシャッター音を消せない。OS が写真撮影の処理に音を
結び付けているためで、設定では変更できない。一方で、カメラの映像を画面に流す処理は
その対象に入っていない。このページは映像から 1 コマを取り出して画像として保存するため、
音が鳴らない。市販の無音カメラアプリと同じ考え方を、ブラウザの上で実現している。

## 対応環境

iOS の Safari を対象としている。合成処理に WebGL2 を使うため、iOS 15 以降を想定している。
実際に動かして確かめたのは iPhone 1 台（iOS 18.7、Safari 26.6.1）だけである。
Android の Chrome でも動作するが、Android は端末側でシャッター音を消せる機種が多く、
このページが想定している場面ではない。

## 使い方

1. 上の URL を iPhone の Safari で開く。
2. 共有メニューから「ホーム画面に追加」を選ぶ。
3. ホーム画面のアイコンから起動する。カメラの使用を尋ねられたら許可する。
4. 画面下の丸いボタンで撮影する。
5. 「保存」を押し、共有メニューの「画像を保存」を選ぶと写真アプリに入る。

ホーム画面から起動するたびにカメラの許可を尋ねられる。理由と対処は後述する。

## 三つの撮影方法

画面下のボタンで切り替える。

| 名前 | 内容 |
| --- | --- |
| 通常 | 映像から 1 コマを取り出す。いちばん速く、既定の方法 |
| 合成 | 連続して取り込んだ複数のコマを重ね、ノイズを減らす |
| 写真API | 端末内部の写真撮影の仕組み（`ImageCapture.takePhoto`）を使う |

通常と合成は、写真撮影の仕組みを通らないため音が鳴らない。

写真API は本来なら音が鳴る経路である。手元の 1 台ではどの解像度でも鳴らなかったが、
WebKit 側に音を止める処理は無く、この経路が音の対象から外れているだけなので、
端末や iOS の版によっては鳴る可能性がある。解像度も映像と同じで、画素数は増えない。
以上の理由から既定にはしておらず、選んだときに一度だけその旨を表示する。

## 画質について

映像から取り出した 1 コマは、純正カメラの写真処理（Deep Fusion など）を通らないため、
1 枚だけでは純正に及ばない。合成撮影はこの差を埋めるための機能である。

- 連続して取り込んだコマを、画素より細かい単位で位置を合わせて重ねる。
- 重ねた枚数を N とすると、ランダムなノイズはおよそ 1/√N に減る。8 枚で約 1/2.8 になる。
- 明るさはガンマ 2.2 で近似的に直線化してから平均する。暗部の濁りを避けるため。
- 手ぶれによる画素以下のずれを利用して、2 倍の格子に重ねることもできる（ドリズル）。
- 基準のコマから大きく外れた画素は重みを下げるため、多少の動きがあっても像が重ならない。

止まっているものや暗い場所では効果が大きい。動いているものや、純正の写真に近い解像感を
求める場面では向かない。

## 実測でわかったこと

iPhone 1 台（iOS 18.7、Safari 26.6.1）での測定値である。詳細は
[docs/FINDINGS.md](docs/FINDINGS.md) にまとめてある。

| 項目 | 結果 |
| --- | --- |
| 取得できる最大の解像度 | 2160×3840、毎秒 30 コマ |
| 通常撮影の所要時間 | 45 ミリ秒から 214 ミリ秒（解像度による） |
| 写真API の所要時間 | 335 ミリ秒から 589 ミリ秒。起動後の 1 枚目は 1 秒から 1.4 秒 |
| 写真API の解像度 | 映像と同じ。大きさを指定しても同じ値に調整される |
| 写真API の音 | 720p、1080p、4K のいずれでも鳴らなかった |
| 保存できる形式 | JPEG と PNG。HEIC と AVIF は指定しても中身が PNG になる |
| ズームとライト | 0.5 倍から 10 倍のズームと、ライトの操作に対応 |

「iOS Safari では 720p までしか取得できない」という記述を各所で見かけるが、
少なくとも現行の iOS では当てはまらない。

## カメラの許可について

ホーム画面に追加したページは、起動のたびに新しい文書として読み込まれる。iOS はこの形の
ページに対してカメラの許可を保持しないため、起動のたびに許可を尋ねられる。ページ側から
これを取り除く方法は無い。そのうえで、尋ねられる回数が増えないように次の実装にしてある。

- 起動と同時にカメラを要求する。操作は許可を選ぶ 1 回だけで済む。
- 許可が残っているかどうかを、カメラを開く前に判定する。残っていればそのまま映像を出す。
- 解像度を変えるときは、映像を取り直さずに設定だけを変更する。
- 別のページへ移動する前に確認を出す。移動すると文書が変わり、許可を取り直しになるため。

設定アプリの「アプリ」から Safari を開き、「カメラ」を「許可」にすると尋ねられなくなる
場合がある。すべてのサイトに許可が下りる設定なので、内容を理解したうえで選んでほしい。
その端末で許可が保持されるかどうかは、`diag.html` の「カメラの許可が残っているか」で確認できる。

## 端末チェック

`diag.html` は、この端末で何ができるかを実際に測るページである。解像度の候補、カメラの機能、
1 コマを取り出す速さ、連写の速さ、写真API の挙動（音の有無は手で記録する）、GPU、
保存できる形式を調べ、結果を JSON で出力する。測定値は `docs/FINDINGS.md` に追記して残す。

## 開発

ビルドは不要で、静的ファイルをそのまま配信する。

```sh
npm test            # 位置合わせと合成の単体テスト。追加の依存なしで動く
npm run test:e2e    # Chromium での通し確認。事前に npm i -D playwright が必要
npm run icons       # アイコンの生成。python3 が必要
npm run serve       # ローカルで確認する。カメラは https か localhost でのみ動く
```

GPU で動く合成処理は、同じ計算を CPU でも実装してある。両者が一致するかどうかは
`diag.html` の「GPU と CPU を照合する」で確認できる。開発機では GPU の処理を
そのまま検証できないため、この照合を端末上で行っている。

公開は GitHub Pages を使っている。リポジトリの Settings から Pages を開き、
公開元として `main` と `/ (root)` を選ぶ。`.nojekyll` を置いてあるので、
ファイルは変換されずにそのまま配信される。

## 扱いについて

撮影した画像はこの端末の中だけで処理し、どこにも送信しない。Service Worker が保存するのは
ページを構成するファイルだけで、画像は含まない。

個人で使うために公開しているもので、ライセンスは付けていない。

撮影してよい場所かどうかを確かめて使ってほしい。日本では 2023 年 7 月に
性的姿態等撮影罪が施行され、同意のない撮影が処罰の対象になる場面がある。
